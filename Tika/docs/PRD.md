# PRD.md - Tika (Ticket + Kanban Board)

## 1. 제품 개요

Tika는 **티켓 기반 칸반 보드 TODO 앱**이다. 사용자는 할 일을 "티켓" 단위로 등록하고, 고정된 컬럼 사이를 드래그 앤 드롭으로 이동시키며 진행 상태를 관리한다. 각 티켓은 계획일과 실제일을 함께 기록하여 일정 준수 여부를 추적할 수 있다.

Next.js App Router 기반으로 프론트엔드와 백엔드를 디렉터리 수준에서 분리하며, `src/shared/`를 통해 타입과 검증 스키마를 공유한다 (자세한 구조는 [CLAUDE.md](../CLAUDE.md) 참고).

## 2. MVP 범위

| 항목 | 내용 |
|---|---|
| 사용자 | 단일 사용자 (로그인/인증 없음) |
| 컬럼 구성 | 고정 4컬럼: `Backlog` / `TODO` / `In Progress` / `Done` |
| 티켓 기능 | 생성(Create), 조회(Read), 수정(Update), 삭제(Delete) |
| 상태 이동 | 드래그 앤 드롭으로 컬럼 간 이동 |
| 일정 필드 | 계획 시작일, 시작일, 계획 종료일, 종료일 |

## 3. 2차 범위 (MVP 제외)

다음 항목은 2차 스펙으로, MVP 구현에서 **명시적으로 제외**한다.

- 인증 / 로그인
- 커스텀 컬럼 (컬럼 추가/삭제/이름변경)
- 멀티유저 (동시 편집, 담당자 배정 등)
- 라벨 / 코멘트
- 파일 업로드

## 4. 사용자 시나리오

```
할 일 등록 → 상태 이동 → 수정/삭제 → 완료 확인
```

1. **할 일 등록**: 사용자가 Backlog에 새 티켓을 생성하고 계획 시작일/계획 종료일을 입력한다.
2. **상태 이동**: 작업을 시작하면 TODO → In Progress로 티켓을 드래그하여 이동시키고, 실제 시작일이 기록된다.
3. **수정/삭제**: 진행 중 내용이 바뀌면 티켓을 수정하고, 더 이상 필요 없는 티켓은 삭제한다.
4. **완료 확인**: 작업이 끝나면 티켓을 Done으로 이동시키고, 종료일이 기록되어 완료 여부를 확인한다.

## 5. 핵심 기능 목록

REQUIREMENTS.md의 FR-001 ~ FR-008과 대응하는 기능은 다음과 같다.

| ID | 기능명 | 설명 |
|---|---|---|
| FR-001 | 티켓 생성 | 사용자가 제목, 설명, 계획 시작일/계획 종료일을 입력하여 새 티켓을 생성한다. 생성된 티켓은 기본적으로 Backlog 컬럼에 배치된다. |
| FR-002 | 티켓 조회 | 보드에 표시된 모든 티켓과 각 티켓의 상세 정보(제목, 설명, 일정 필드, 현재 상태)를 조회할 수 있다. |
| FR-003 | 티켓 수정 | 기존 티켓의 제목, 설명, 일정 필드를 수정할 수 있다. |
| FR-004 | 티켓 삭제 | 더 이상 필요 없는 티켓을 보드에서 삭제한다. |
| FR-005 | 드래그 앤 드롭 상태 이동 | 티켓을 마우스/터치로 드래그하여 다른 컬럼으로 이동시키면 티켓의 상태 값이 갱신된다. |
| FR-006 | 고정 4컬럼 보드 표시 | Backlog / TODO / In Progress / Done 4개 컬럼을 항상 고정된 순서와 레이아웃으로 표시한다. |
| FR-007 | 일정 필드 관리 | 티켓별로 계획 시작일, 시작일, 계획 종료일, 종료일 4가지 날짜 필드를 저장하고 표시한다. |
| FR-008 | 완료 확인 | 티켓이 Done 컬럼으로 이동하면 종료일이 기록되고, 계획 종료일과 비교하여 일정 준수 여부를 시각적으로 확인할 수 있다. |

## 6. 기술 스택 요약표

CLAUDE.md에 정의된 기술 스택과 선정 이유는 다음과 같다.

| 구분 | 기술 | 선정 이유 |
|---|---|---|
| Framework | Next.js 15 (App Router) | 프론트엔드/백엔드를 하나의 프로젝트에서 디렉터리 수준으로 분리 관리 가능, Route Handler로 API 서버 역할 겸용 |
| Language | TypeScript (strict) | 컴파일 타임 타입 검증으로 런타임 오류 사전 방지, `any` 금지 규칙과 함께 타입 안정성 강화 |
| Frontend | React 19 | 최신 컴포넌트 모델과 동시성 렌더링 지원, Next.js 15와 호환성 최적화 |
| Styling | Tailwind CSS 4 | 유틸리티 클래스 기반으로 빠른 UI 개발 및 일관된 디자인 시스템 유지 |
| Drag & Drop | @dnd-kit/core + @dnd-kit/sortable | 접근성(a11y)을 지원하는 드래그 앤 드롭 라이브러리, 칸반 보드의 컬럼 간 이동 구현에 적합 |
| ORM | Drizzle ORM | 타입세이프 쿼리 작성 가능, 경량이며 Zod와 스키마 연동이 쉬움, raw SQL 없이 안전한 DB 접근 |
| DB | Vercel Postgres (Neon) | 서버리스 Postgres로 Vercel 배포 환경과 네이티브 통합 |
| Validation | Zod | 런타임 요청 검증과 TypeScript 타입 추론을 동시에 처리, `src/shared/validations`에서 프론트/백엔드 공유 |
| Testing | Jest + React Testing Library | 단위/컴포넌트 테스트 작성 용이, TDD 사이클(TEST_CASES.md 우선 작성) 지원 |
| Deployment | Vercel | Next.js와 네이티브 통합된 배포 파이프라인, Postgres(Neon)와 함께 원스톱 운영 |

## 7. 와이어프레임 참고

보드 레이아웃은 **좌측 Backlog 사이드바 + 우측 3컬럼 보드(스윔레인)** 구조를 따른다.

```
┌───────────────┬─────────────────────────────────────────────────────────┐
│               │                     Tika Board                          │
│   Backlog     ├───────────────────┬───────────────────┬─────────────────┤
│  (사이드바)     │       TODO         │   In Progress      │       Done       │
│               │                   │                   │                 │
│ ┌───────────┐ │ ┌───────────────┐ │ ┌───────────────┐ │ ┌─────────────┐ │
│ │ Ticket A  │ │ │  Ticket D     │ │ │  Ticket F     │ │ │ Ticket H    │ │
│ └───────────┘ │ └───────────────┘ │ └───────────────┘ │ └─────────────┘ │
│ ┌───────────┐ │ ┌───────────────┐ │                   │ ┌─────────────┐ │
│ │ Ticket B  │ │ │  Ticket E     │ │                   │ │ Ticket I    │ │
│ └───────────┘ │ └───────────────┘ │                   │ └─────────────┘ │
│ ┌───────────┐ │                   │                   │                 │
│ │ Ticket C  │ │                   │                   │                 │
│ └───────────┘ │                   │                   │                 │
│               │                   │                   │                 │
│  [+ 티켓 추가]  │                   │                   │                 │
└───────────────┴───────────────────┴───────────────────┴─────────────────┘
```

- **좌측 Backlog 사이드바**: 아직 착수하지 않은 전체 티켓 목록을 세로 스크롤 형태로 표시. 신규 티켓 생성 버튼 포함.
- **우측 3컬럼 보드 (TODO / In Progress / Done)**: 실제 작업 진행 상태를 스윔레인 형태로 표시하며, 각 컬럼 간 티켓 드래그 앤 드롭 이동 가능.
- 각 티켓 카드에는 제목과 일정 요약(계획 시작일 ~ 계획 종료일)이 표시되고, 클릭 시 상세 정보(4개 날짜 필드 포함)를 확인/수정할 수 있다.
